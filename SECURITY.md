# Security Policy

## Supported versions

Security fixes are intended for the current development branch and the latest published release. Older releases may not receive fixes; upgrade to the latest release before reporting an issue.

## Reporting a vulnerability

Please do **not** open a public issue for an undisclosed vulnerability.

1. Use GitHub's **Private vulnerability reporting** feature from the repository's Security tab when it is enabled.
2. If private reporting is unavailable, contact the repository maintainer privately through the GitHub profile linked from the repository.
3. Include the affected commit/version, prerequisites, a minimal reproduction, impact, and any suggested mitigation. Avoid including real credentials or unrelated personal data.

Please allow the maintainer a reasonable opportunity to investigate and prepare a fix before public disclosure. This project does not currently publish a formal response-time SLA or a bug-bounty program.

See [`docs/security.md`](docs/security.md) for the application's security model and third-party trust boundaries.
